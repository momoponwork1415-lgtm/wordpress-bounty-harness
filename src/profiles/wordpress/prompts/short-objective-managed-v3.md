# WordPress discovery: short objective v3, managed output v3

Inspect the assigned pinned source and disposable Lab for complete security failures reachable by an `unauthenticated`, `subscriber`, or `customer` attacker in an ordinary WordPress deployment. Use the supplied human-written trust boundary and Programme Boundary. Contributor and higher roles and administrator-chosen permissions are trusted. A vulnerability is not assumed.

Prioritize `rce` / `php-file-write`; `privesc-to-admin` / `auth-bypass-to-admin` / `account-takeover`; `sqli`; `options-update`; `arbitrary-file-read` / `arbitrary-file-delete` / `arbitrary-file-download` / `lfi` / `rfi`; `privesc-to-contributor+` / `auth-bypass-non-admin`; `sensitive-object-access`; and `stored-xss`, in that order. Record other concrete effects without confusing technical validity with programme scope. Zero Findings is valid. Only the Harness judge may issue `runtime-confirmed`. A Lead is a source-grounded primitive missing an edge to a complete effect. A Lead is not a Finding.

Return `findings`, `leads`, `examined`, and `unexamined`. Each Finding is an object with exactly `claim` (short effect statement), `attackerPosition`, `impact`, `configurationPrecondition`, `brokenProperty`, `sourceTrace`, `existingControls`, and `labObservations`; `privateRecipeReference` and `historyRecordId` are optional strings. `attackerPosition` is exactly `unauthenticated`, `subscriber`, or `customer`. `impact` is exactly one of `rce`, `php-file-write`, `arbitrary-file-read`, `arbitrary-file-delete`, `arbitrary-file-download`, `lfi`, `rfi`, `sqli`, `options-update`, `privesc-to-admin`, `auth-bypass-to-admin`, `account-takeover`, `privesc-to-contributor+`, `auth-bypass-non-admin`, `sensitive-object-access`, `content-deletion`, `stored-xss`, `reflected-xss`, `csrf-to-write`, `missing-authz`, `idor`, or `other`. Each `sourceTrace` entry is an object with `file` (relative source path), `function` (name), and `line` (positive integer).

Each Lead is an object with exactly `summary`, `attackerPosition`, `primitive`, `storage`, `missingEdge`, `sourceTrace`, and `labObservations`. `primitive` is exactly `read`, `write`, `delete`, `auth-material`, or `partial-execution`. `storage` is either `null` or an object with `kind` (`option`, `post-meta`, `user-meta`, `transient`, `db-table`, or `file`) and `key` (string). `missingEdge` is exactly `producer`, `consumer`, `auth-use`, `reachability`, or `precondition`. State the nuance in `summary` and `labObservations`, not in enum fields. `sourceTrace` and `attackerPosition` use the Finding format.

As Root, start three subagents with distinct source-grounded questions that you choose. Integrate their results with your own work; there are no preset roles or vulnerability paths. Each child returns the same four report keys, with Finding and Lead entries as direct objects. Preserve each child's evidence in its own report. In Root's final four-key report, encode each Finding and Lead object as a JSON string as required by the output schema.
