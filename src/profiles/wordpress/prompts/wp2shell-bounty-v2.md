# WordPress discovery: WP2Shell bounty v2

Investigate the pinned target source and disposable Lab from first principles. Find complete security failures reachable by an `unauthenticated`, `subscriber`, or `customer` attacker in an ordinary WordPress deployment. A vulnerability is not assumed. The supplied trust boundary and Programme Boundary define the allowed attacker position and priorities; contributor and higher roles and administrator-chosen permissions are trusted. The defect must be attributable to the target, although pinned WordPress or required dependency source may complete a chain.

Prioritize `rce` / `php-file-write`; `privesc-to-admin` / `auth-bypass-to-admin` / `account-takeover`; `sqli`; `options-update`; `arbitrary-file-read` / `arbitrary-file-delete` / `arbitrary-file-download` / `lfi` / `rfi`; `privesc-to-contributor+` / `auth-bypass-non-admin`; `stored-xss`; and `sensitive-object-access`, in that order. Record other concrete effects without treating programme eligibility as technical validity. Do not turn a partial primitive into a Finding merely to fill the report.

As Root, start three subagents with genuinely different questions grounded in the assigned source. Choose the questions from the target's actual entry points, data flows, state transitions, and interactions; do not give them preset vulnerability types or tell them all the currently favored route. Investigate cross-file and cross-feature chains yourself. Keep a private registry of approach families, their source evidence, contrary evidence, blocked routes, and unresolved questions. When agents converge on one family, redirect the next wave toward a different source-grounded family. Keep independent approaches alive long enough to test their real strengths and gaps.

After each wave, synthesize the children’s evidence, challenge promising routes, and choose another wave when a concrete question remains. Do not stop because the first wave found nothing. For each proposed chain, test attacker control, reachability, capability and nonce checks, transformations, persistence, the later consumer, ordinary configuration, and the behavior of pinned dependencies where relevant. Combine partial routes only when every connecting edge has source or Lab support. A missing required dependency or Lab setup is an unresolved precondition, not evidence that the route is safe.

Before concluding the Trial, spend at least 30 minutes of actual exploration and run at least two distinct waves, including a wave on a different approach family after the first complete priority Finding. Work on new source-grounded questions during that time; do not wait idle or invent elapsed time. You may finish earlier when the Lab is unusable, the provider interrupts, or the externally enforced run limit is reached. After the effort floor, stop when two consecutive waves add no new approach family, material evidence, or concrete unresolved question. Report the strongest surviving Lead and exact gap rather than implying the target is secure.

Return `findings`, `leads`, `examined`, and `unexamined`. Each Finding is an object with exactly `claim` (short effect statement), `attackerPosition`, `impact`, `configurationPrecondition`, `brokenProperty`, `sourceTrace`, `existingControls`, and `labObservations`; `privateRecipeReference` and `historyRecordId` are optional strings. `attackerPosition` is exactly `unauthenticated`, `subscriber`, or `customer`. `impact` is exactly one of `rce`, `php-file-write`, `arbitrary-file-read`, `arbitrary-file-delete`, `arbitrary-file-download`, `lfi`, `rfi`, `sqli`, `options-update`, `privesc-to-admin`, `auth-bypass-to-admin`, `account-takeover`, `privesc-to-contributor+`, `auth-bypass-non-admin`, `sensitive-object-access`, `content-deletion`, `stored-xss`, `reflected-xss`, `csrf-to-write`, `missing-authz`, `idor`, or `other`. Each `sourceTrace` entry is an object with `file` (relative source path), `function` (name), and `line` (positive integer).

Each Lead is an object with exactly `summary`, `attackerPosition`, `primitive`, `storage`, `missingEdge`, `sourceTrace`, and `labObservations`. `primitive` is exactly `read`, `write`, `delete`, `auth-material`, or `partial-execution`. `storage` is either `null` or an object with `kind` (`option`, `post-meta`, `user-meta`, `transient`, `db-table`, or `file`) and `key` (string). `missingEdge` is exactly `producer`, `consumer`, `auth-use`, `reachability`, or `precondition`. State the nuance in `summary` and `labObservations`, not in enum fields. `sourceTrace` and `attackerPosition` use the Finding format. A Lead is not a Finding.

As Root, start three subagents with distinct source-grounded questions that you choose. Integrate their results with your own work; there are no preset roles or vulnerability paths. Each child returns the same four report keys, with Finding and Lead entries as direct objects. Preserve each child's evidence in its own report. In Root's final four-key report, encode each Finding and Lead object as a JSON string as required by the output schema.
