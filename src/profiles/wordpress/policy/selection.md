# WordPress 対象選定方針

正本の設定は [selection.json](selection.json)。`loadWordPressSelectionPolicy()` で読み込む。

- 本番の `candidateSource` は WordPress.org の人気順・タグ順を列挙する。取得元、観測時刻、応答 digest を記録し、取得不能・期限切れの一覧からは候補を採らない。`candidateSlugs` と `pinnedVersions` は開発対象を手動固定する旧形式として残す。両形式は union で分ける。選定の適格性と順序は `select(policy)` が機械的に決め、人間の対象承認は置かない。
- 必須pluginは対象のメインPHPファイルの `Requires Plugins` ヘッダから取得する。同じ先頭8 KiBに `WC requires at least:` または `WC tested up to:` が値付きであれば、`woocommerce` を依存に足す（`Requires Plugins` と重複しても1件。WooCommerce自身は自分に依存しない）。ヘッダは必須と任意の連携を区別しないので、任意連携の対象にも WooCommerce が入る。どちらのヘッダにも現れない依存は選定方針の `pluginDependencySlugs` に対象slugごとに明示する。本番の自動選定では `pluginDependencySlugs` にslugを挙げ、freeze時点の公式stable版を固定する。現行 Unlimited Elements はヘッダが依存を宣言しないため、既定方針で Elementor を指定する。手動の開発・歴史的評価は `pluginDependencyPins` に版を指定する。過去の評価対象に用いた [Unlimited Elements 2.0.16 の Elementor 4.2.0 pin](../../../../docs/evaluation/public-source-pins.json) は現行版の既定値へ流用しない。取得失敗時に依存を省略して探索やLabを起動しない。依存の指定変更は選定方針digestを変え、Snapshotには取得した版とsource digestが残る。
- 本番の install 下限は正本の `minimumActiveInstallations`。programme scope の報奨下限とは別に適用する。 上限は `maximumActiveInstallations`（既定 1,000,000、同数以上を `above-installation-ceiling` で落とす）。所有者が 2026-10-16 に「数十万規模を主にする」と決めたもの。`cascade` は主帯が `select` の `--minimum`（runner は 1）に満たないときだけ順に試す段の配列で、各段は主方針に `minimumActiveInstallations` / `maximumActiveInstallations`（`null` で上限なし）/ `minimumPayingClassCount`（mirror の paying class 記録数がこれ未満なら `below-paying-class-minimum`）を重ねたもの。現行は 50k → ≥1M かつ paying class ≥2 の順（所有者の順、ADR 0037 の 2026-10-19 追記。2026-10-26 に所有者が active install を 50,000 以上に限ると決め、30k の段を外した。ADR 0037 の 2026-10-26 追記）。段で選ばれた対象は `cascadeStep`（1 始まり）を `TargetSelection`、選定レポート、台帳の `target-selected` に持つ。方針 digest は主方針のもの 1 つで、段ごとに変わらない。WordPress core 版は `wordpressVersion` で固定し、選ばれた対象の Snapshot を作ってから台帳に記録する。
- 選ばないもの：WordPress.org 非掲載、観測不能、観測期限切れ、配布停止。配布停止は理由コード `distribution-closed` で区別する。
- `excludedAuthors` は、公式プログラムの対象外資産（Automattic、Facebook、Google、SiteGround、Yoast）の作者を除く。WooCommerce 名義と MailPoet 名義の plugin は Automattic 資産なので `WooCommerce` と `MailPoet` も入れる（2026-10-17。本番 batch 5 で google-listings-and-ads と woocommerce-payments が選ばれた抜けの修正）。作者情報が取れない対象は適格にしない。
- `excludedSlugs` には、作者名だけでは所有関係を断定できないものと、ベンダー側のweb serviceが無いと動かないものを手で入れる。後者はメタデータから機械的に判定できないため、タグからは推定しない。
- `maximumTargets` は週の対象数。`select` が台帳の過去選定と Finding を除いた候補をスコア順に補充して返す。`revisitPolicy` は版上昇・prompt 版変更時の再訪を指定するが、未公開 Finding がある対象は再訪しない。現行方針は `{ "kind": "version-increased", "minimumDaysSinceTrial": 90 }`: WordPress.org の現行 stable 版が台帳に数えた同 slug の全 Trial の版より高く、かつ最後の Trial 開始から 90 日以上経っていれば戻す（[ADR 0037](../../../../docs/adr/0037-selection-uses-advisory-history-counts.md) の 2026-10-19 追記。同一 plugin の paying class 記録の間隔 中央値 42 日、所有者の有償 18 件中 5 件が版上昇後の再報告）。旧世代の `legacy-started` は戻らない。次の campaign は最新の選定バッチに固定された対象と Snapshot を使う。
- `maximumObservationAgeDays` と `maximumUpdateAgeDays` は別々の鮮度制限。Wordfence programme 方針の観測も `current` である必要がある。
- 公開履歴はローカル Wordfence mirror（host 設定 `wordfenceHistory`）の **件数と公開日だけ** を採点に使う（[ADR 0037](../../../../docs/adr/0037-selection-uses-advisory-history-counts.md)、ADR 0030 を上書き）。slug ごとに、mirror の `last_successful_at`（asOf）から `historyWindowDays`（既定 365）前までに公開された非 informational の plugin 記録の件数 `count`、そのうち signal の class 名が `historyPayingClasses` に入る件数 `payingClassCount`、最新公開日 `latestPublished` を取る。3 項を採点する（いずれも基準は asOf で壁時計ではない）: `history = scoreWeights.history × min(count, historyCountCap) / historyCountCap`、`historyPayingClass = scoreWeights.historyPayingClass × min(payingClassCount, historyPayingClassCap)`（1 件 1 点、正規化しない。上限既定 3）、`recordRecency = scoreWeights.recordRecency × max(0, 1 − 最終記録からの日数 / historyWindowDays)`（最新記録が asOf なら 1、window の端か記録なしで 0）。現行の重みは `installations: 0.5`（× log10(1 + install)）、`recency: 0`（WordPress.org 更新鮮度はパッチ公開が原因側にある leak）、`history: 0`、`historyPayingClass: 1`、`recordRecency: 1` で、帯内の値域は 0–3 ＋ 0–1 ＋ 2.5–3.0。paying class 件数が順位を決め、新しさが同点を割り、install が最後に効く（[docs/reviews/2026-10-19-selection-statistics.md](../../../../docs/reviews/2026-10-19-selection-statistics.md) §5.1。帯内 top-50 の精度 82% / 86%、旧重みは 52% / 60%）。3 項の重みが全部 0 または欠落なら mirror を開かず従来の順位を再現する。mirror の `last_successful_at` が `maximumHistoryAgeDays`（既定 2）より古い、state と DB が食い違う、host に mirror が無いときは `select` が候補を観測せずに止まる。更新の失敗 flag（`stale_fallback`）だけでは止めず、選定レポートに `lastRefreshFailed` として残す（`history status` は従来どおり flag でも `stale`）。記録の title、CVE、CWE 名、個々の記録の signal 値は読まず、選定レポートと `target-selection.json` には `count` / `payingClassCount` / `latestPublished` / mirror の asOf と digest だけを書く。mirror は探索に渡さない。
- 旧方針の `highThreatTags`、`surfaceTagWeights`、`scoreWeights.surface / highThreat` は 2026-10-19 に削除し、含む file は parse で弾く。それより前に書いた `target-selection.json` の `highThreatSurface` と `scoreBreakdown.surface / highThreat` は読み続ける。順位は公開履歴の paying class 件数、最終記録の新しさ、install 数で決める（ADR 0032 Q5、ADR 0037 とその 2026-10-19 追記）。旧方針の手書き `historySignals` / `historySource` は ADR 0037 で削除し、含む file は parse で弾く。候補タグは Wordfence ミラーと WordPress.org のタグから機械的に出した族で、採点には使わない（ADR 0032 Q3、docs/reviews/2026-10-13-selection-data.md）。
- `scoreWeights` を変えると、install 数、更新の新しさ、公開履歴（件数、paying class 件数、最終記録の新しさ）の寄与が変わる。スコア内訳、方針 digest、観測 ref、履歴の件数と mirror の時点は `TargetSelection` に残る。
- 旧方針の `runBudget` も 2026-10-19 に削除した（古い `target-selection.json` の `runBudget` は読み続ける）。run 数は対象ごとに 1 Trial で、`campaign run --repeat` だけが増やす（ADR 0029）。選ばれた対象を指名したタグは `candidateTag` に残り、半年後にタグ別の有償率を測る材料になる。
