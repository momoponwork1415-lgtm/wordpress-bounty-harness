# 外部サービス接続を前提とする検証 Lab の外向き通信と一時公開を、条件付きの通常運用にする

## 背景

ADR 0041 は 2026-10-26 に所有者が承認した一回限りの実験を記録し、「本番ランナーや次の Lab に適用しない」と定めた。その後、同じ形の検証が繰り返し必要になった。画像最適化、翻訳、フォーム連携のように、外部サービスへの接続がプラグインの通常の利用の前提になっているものでは、接続した状態でなければ入力が sink に届かない。検証の無人化は案件ごとに ADR 0041 と同じ計画を出し、所有者の承認を 1 回ずつ求めていた。所有者は 2026-11-01 に「そもそもこういう時は許可するのは通常運用にしたい」と言い、同日に改訂の開始を認めた。

## 決定

外部サービスへの接続が通常の利用の前提になる検証に限り、次の 6 条件をすべて満たす外向き通信と一時公開を、案件ごとの承認なしに行える。

1. 専用の使い捨て `runsc` Lab で行う。本番ランナー、探索 Trial、通常の検証 Lab のネットワーク既定値は変えない。
2. 出口は、接続に必要なサービスの固定ホスト・ポートだけを通す中継器を経由し、通信を記録する。任意の宛先への直接通信は許可しない。
3. 公開入口は接続確認の間だけ開け、無害な `GET` / `HEAD` の確認用パス（画像など）だけを通す。管理画面、ログイン、REST、投稿、コメント、任意のアップロードは拒む。
4. サービスの API キーと資格情報は所有者が自分で入れる。AI 操作役は扱わない。
5. 攻撃入力を置く前に公開入口と出口を停止し、外部から到達できないことを確かめる。以後の操作と観測は Lab 内だけで行う。入口を再開して攻撃入力を公開しない。
6. 宛先、開閉の時刻、接続応答、停止確認を Private Evidence に残す。

これらを満たさない接続（宛先が確定しない、資格情報を AI が扱う、攻撃入力の後も入口を開けるなど）は、従来どおり所有者の明示の承認を要する。接続の成功や AI の観測は確定の根拠にしない（不変条件 3、ADR 0040）。

## 理由

条件が同じ計画を毎回承認する運用は、所有者の判断点を増やすだけで安全性を足さない。危険の源は「どこへ、いつ、何を通すか」であり、それは 6 条件が固定している。所有者の判断点は「提出前のレビュー」と「外部行動の承認」の 2 つという不変条件 6 の趣旨にも合う。

## 採らなかった選択肢

- 通常の Lab の外向き通信を広げる: 接続を要しない検証まで広がる。
- 案件ごとの承認を続ける: 観測待ちの日数を増やし、重複を招く。
- AI 操作役が API キーを入れる: 資格情報の扱いを Harness の外に出さない方針（不変条件 8）に反する。

## 帰結

- SPEC §2(2) と AGENTS.md の不変条件 2 に、この ADR への参照を 1 文足す。
- OPERATIONS 第 3 節の手順（接続計画の様式、停止確認の記録）は、検証の無人化が別 PR で書く。
- ADR 0041 は実験の記録として残す。「次の Lab に適用しない」の行は、この ADR で置き換える。

## 消し方

この ADR と SPEC・AGENTS.md の参照を revert する。案件ごとの承認に戻る。Private Evidence の記録は残す。
