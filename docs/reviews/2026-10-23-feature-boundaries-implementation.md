## F14 の確認結果

[ADR 0035](../adr/0035-verification-as-a-skill.md) と [#352 の指定事例](https://github.com/momoponwork1415-lgtm/wordpress-bounty-harness/issues/352#issuecomment-6252287001) は、Brizy / TranslatePress 3.2.6 の受け渡しが判定器の結論まで届くことを旧経路の退役条件としている。[受入記録の確認](https://github.com/momoponwork1415-lgtm/wordpress-bounty-harness/issues/352#issuecomment-6306083870) は不足を明記しており、PR のマージだけでは条件を満たさない。

今回の監査でも、指定した両事例の完了を示す記録が揃っていることを確認できなかった。既存の [#353](https://github.com/momoponwork1415-lgtm/wordpress-bounty-harness/issues/353#issuecomment-6366412637) に確認結果を追記した。新しい探索・動的再現は行っていない。旧経路、共有 Lab、判定器、既存証拠は削除しない。

## 互換性と確認の限界

- 保存済みイベントと資料の形式を変えず、過去の判断は export に残す。現在の一覧は現在の検証に対応する判断だけを使う。
- 要求した資料そのものが欠損していればエラーにする。古い非標準 identity の scope 評価を ID で探す互換経路には、全件読取りが残る。
- 対象の探索、検証の方法、承認条件、本番運転の変更は含まない。確認に使うのは合成データの回帰テストであり、実 Lab の移行受入を代替しない。
