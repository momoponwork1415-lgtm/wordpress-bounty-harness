## 2. PR #265（branch `codex/issue-242-durable-stop`、Issue #242）

```text
PR #265 のレビュー comment（2026-10-16）を直す。方向は最終設計 第 3.1 節と #242 受入 (8)「起動時は死んだ pid と前回の stop marker を消してから始める」。所有者は durable stop の反転を採らない。

1. src/cli/continuous.ts の onSignal から requestContinuousStop の呼び出しを外す。SIGINT / SIGTERM は「今の対象の境界で止める」だけにし、永続的な operator marker を残さない。systemctl restart、host 再起動、wsl --shutdown の後は、runner が人間なしで再開する。
2. continuous.stop を残す（latch する）のは、明示の continuous stop コマンドが書いた marker だけにする。その marker は continuous resume または run --resume で解除する、という本 PR の仕組みはそのまま使ってよい。
3. 「停止中の起動は作業開始前に終える」「status が停止処理中と stale pid を表示する」は残す。
4. docs/OPERATIONS.md 第 2 節の continuous run の説明と 8.2 の保守一覧を、上の挙動に合わせる（SIGTERM では止まらない、continuous stop だけが残る）。
5. テスト: (a) SIGTERM → 再起動で marker が無く再開する、(b) continuous stop → 再起動で止まったまま、(c) resume で再開、の 3 本を公開 interface（createContinuousRunner の注入 seam）から書く。

上位の #266（停止理由の保存）、#267（待機期限の復元）、#268、#269 はこの branch の上に積まれているので、この修正後にそれぞれ main を merge し直す。
```
