# #215 旧探索履歴 coverage の現状確認（2026-10-14）

調べて報告。これは正本や初回 Trial の起動許可ではない。対象は現ホストで確認できた保存状態と、#215 の既往 Trial gate の実装である。未公開 Finding、対象名、旧記録の本文はこの文書に含めない。

## 確認できた事実

- 現存する state inventory は 22 個の state 台帳を列挙している。同じホストで観測した state 台帳は 30 個で、8 個が inventory に入っていない。
- 省略された台帳には `discovery-run-started` が合計 227 行ある。この行数には探索以外が混ざり得るため、独立した探索 Trial 数や対象数とは扱わない。
- 現ホストの標準位置に、ホスト共通の Trial registry と完全監査済み coverage manifest は見つからなかった。したがって inventory の存在だけで初回適格性は証明できない。
- 既知の保存場所に限ったメタデータ上の候補ファイル数は、旧研究 DB 候補 732、旧 queue 関連 3,181、archive 274 だった。これらは source 全体の列挙でも、各ファイルが探索開始記録を持つという判定でもない。ファイル内容の digest も取っていない。
- 所有者が明示的に許可した旧 queue の単一ファイルを、slug・状態・開始時刻だけで集計した。172 行に 153 slug があり、開始時刻を持つのは 163 行・148 slug だった。現在の状態は `done` 140 行、`failed` 28 行、`capped` 2 行、`queued` 2 行で、`queued` の 2 行にも開始時刻が残っている。開始時刻だけでは agent の探索 Trial 開始を断定しない。
- 旧研究 DB と現行 state 台帳は記録形式が異なる。旧 queue と他の記録の重複や対象の同一性は未照合である。

## 未確認と制約

旧記録の開始事実を plugin slug へ一意に対応付ける作業、4 区分の完全な source roster、source cut と旧 writer の停止証拠、内容・監査根拠の digest は未作成である。旧 source の更新停止を現時点のファイル状態だけから証明することもできない。

省略台帳の `event_json` 全文を解析して探索開始だけを数える操作は、未公開 Finding を含む可能性があるとして自動承認審査に拒否された。この操作は再試行していない。上記 227 行の内訳は未確認のままとする。

別の旧 DB メタデータ監査で確認された追加の 29 slug と、旧 queue の集合との重複も未測定である。旧 DB の slug は独立した列ではなく `payload_json` 内にあり、今回の許可範囲では読み出していない。重複は 0〜29 slug の範囲から狭められず、既往の総数へ単純加算しない。

`repeatTrialCoverageManifestSchema` は4区分の監査結果の形と内部整合性を確認するが、列挙漏れ、監査内容の真偽、承認者の身元、cut 後の外部変更は証明しない。現行のテストにある完全 coverage は合成した入力であり、旧データの実監査ではない（[運用手順](../OPERATIONS.md)、[ADR 0032 Q6](../adr/0032-owner-decisions-on-constraints-2026-10-13.md)）。

## 安全な次の手順

1. 省略された8個を含め、既知の全 state 台帳を再棚卸しする。旧研究 DB・queue・archive も出典ごとに分類し、重複した写しと探索開始記録を区別する。
2. 旧 writer の停止と監査時点の固定を独立した証拠で確認する。旧 source の調査結果、曖昧な対象、監査根拠、内容 digest は Git 外に保管する。slug を一意に復元できない開始記録が残る場合は初回適格と判定しない。
3. 完全な4区分の coverage manifest を独立して査読し、所有者の承認後に明示的に取り込む。取り込み後も新しい未登録 state や監査時点以前の記録が見つかれば coverage を失効させる。

現状では、新しい slug の初回探索 Trial は保留する。同じ slug の追加探索には ADR 0032 Q6 に従う Trial ごとの事前承認が必要である。
